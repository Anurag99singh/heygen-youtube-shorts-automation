# Set up my Shorts workflow

Use this skill when the user asks to set up this plugin. Read [pipeline](../run-shorts-pipeline/SKILL.md), [writer](../write-shorts-script/SKILL.md), [template](../write-shorts-script/template.md) and [scheduler prompts](scheduler-prompts.md). User authorization to set up permits creating a new workbook, configuring selected private avatar group's fixed voice and creating/enabling the three schedulers after verification. It does NOT authorize generating a video, creating a test post, publishing, or modifying another installation.

## Keep the manual work small
Ask only for necessary app sign-ins, avatar choice and ambiguous YouTube destination. Do not ask the owner to find technical IDs or create a GitHub repository. Plugin files already contain the skills. GitHub is optional for version control, not a runtime dependency. Never request passwords, tokens, API keys or secret exports. Plus subscription alone does not prove app, custom-plugin or scheduler availability in a given interface.

## Setup order
1. Verify installed skill access and discover connected Google Drive/Docs/Sheets, HeyGen and Buffer tools. The manifest declares the verified Google Drive and HeyGen app IDs. Buffer must be found through plugin discovery/manual connection because no canonical Buffer app ID was verified at packaging time. Search the live plugin directory; if found suggest the exact returned dependency. If unavailable, ask the user to connect Buffer in the current interface and stop dependent steps. Do not invent an app ID, MCP server URL or publication backend. OAuth/sign-in is completed by the user.
2. Reconcile an existing Setup Receipt in this conversation or an owner-selected prior installation before creating anything. If no known receipt, search Drive for exact workbook title `HeyGen Shorts — Approval Queue`; inspect candidate Settings for installation marker `heygen-shorts/v1` and owner, ask if ambiguous, never silently reuse the sender's or another installation's workbook. A setup retry must resume recorded resource/task IDs rather than duplicate them.
3. Read and follow the host's available Google Sheets skill to create ONE fresh native spreadsheet with `Video Queue`, `Avatar Library` and `Settings`. Use pipeline A:Z mapping. Initialize only headers, no copied pilot videos/news, approvals or checkpoints. Freeze headers, wrap text and set E/I dropdowns PENDING/APPROVE/REVISE; G references Avatar Library; L supports READY, WRITING, SCRIPT REVIEW, RENDERING, VIDEO REVIEW, SCHEDULED, PUBLISHED, BLOCKED, HOLD, CANCELLED. Read metadata and verify before updates. Preserve prior data on setup retry.
4. Discover actual completed avatar looks in the connected HeyGen account, using list tools/preview chooser. Populate Avatar Library with clear numbered distinct labels, full look IDs, orientation. Show supported avatar previews, not private image URLs. Ask user to choose a default; G permits per-row overrides. Do not select a presenter silently. Check fixed voice `Anshul -- 17`, expected ID `d35557f1a8e24de1a34345cf58a30e51`, exists and is ACTIVE. If missing, block and explain; never substitute a similar name. Verify/configure chosen private group default to that voice and read it back. Video Agent has no direct voiceId argument: inspect scene voice IDs afterward, do not promise enforced fidelity.
5. Discover current Buffer organization and YouTube channel. Ask only if ambiguous. Verify connected/unlocked destination, external YouTube identity, timezone, automatic publishing. Store exact observed IDs in Settings. Never reuse IDs from examples. Set Asia/Kolkata; script drafting10:00; default next production-day09:00 publication; preserve required script and video manual gates. Save fixed voice, selected avatar/default group, actor/account confirmation, Sheet URL and plugin version. Never store credentials or signed MP4 URLs.
6. Read scheduler-prompts.md. Inspect actual existing tasks by Sheet ID and role. Create or update EXACTLY THREE pipeline tasks in the user's account using host automation tools. Use actual current time; draft daily10:00 exact_schedule in Asia/Kolkata, completion and approvals hourly condition_watch. Replace every Sheet placeholder with this new verified Sheet ID; include explicit installed plugin/skill names, worker isolation and approval constraints. Store actual IDs, schedules and enable states in Settings and Setup Receipt. Do not modify unrelated research or other workflows. Enable only after all required dependencies, skills, Sheet, identity and destination checks pass. If automation creation or scheduled access to installed skills/dependencies cannot be verified, leave created tasks disabled and report the precise limitation. Native automation availability is runtime-specific; never replace it with an unrequested paid scheduler.
7. Read back Sheet, validation/headers, remote dependency identity, voice, selected avatar and three actual prompts/schedules. Persist a plain Setup Receipt in the Settings tab (and provide a concise copy in chat) with marker `heygen-shorts/v1`, plugin name/version, Sheet ID/URL, default look/group, required voice ID, Buffer organization/channel, task IDs, verified states, unresolved capability checks and next steps. A receipt is not a secret. Scheduled tasks must have this Sheet ID explicitly; never rely solely on chat memory or local files.

## Finish
Give the new Sheet link and a three-task enabled/blocked table. State what is not verified. No generation or Buffer post during setup. Remind owner to enter A=unique Video ID (e.g. VID-001), B=Topic, C=Original Source URL, G=Avatar, L=READY. D is script; E APPROVE/REVISE is human script decision. J is video; I APPROVE/REVISE is human video decision. F is feedback. PENDING waits. Checks are hourly, not instant. Before switching a live installation from another account, coordinate ownership and pause old workers to avoid two actors operating the same queue. New independent installations get new empty queues.
